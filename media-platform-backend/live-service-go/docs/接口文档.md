# live-service-go · 接口文档

> 端口 **9002** ｜ 基础路径 `/api/v1` ｜ 探针 `/healthz`、`/readyz` ｜ 信封/身份/错误码总表见 `../../README.md` §5 ｜ SRS 回调见 §6

---

## 1. 通用约定

- 响应信封 `{"code":0,"message":"success","data":{}}`，`code=0` 成功；时间格式与身份传递见 `../../README.md` §5.1–5.2。
- 身份：`X-User-Id`（uid）、`X-User-Role`（`ADMIN`/`user`）、`X-Session-Id`（游客心跳；缺失时用请求体 `sessionId`）；缺身份头 → `401/40101`，非创建者 → `403/40301`。
- live 专用错误码（通用码 40001/40101/40301/40901/42901/50000/50001 见根 README §5.3）：

| HTTP | code | 含义 |
| --- | --- | --- |
| 404 | 70005 | 直播间不存在 |
| 409 | 70001 | 直播间不在直播中 |
| 409 | 70002 | 推流密钥无效 / 会话不匹配 |
| 409 | 70003 | 直播间数量超出限制 |
| 409 | 70004 | 已有正在直播的直播间 |
| 503 | 70006 | 媒体服务（SRS）不可用 |

- 状态枚举：`IDLE` / `STARTING`（60s 未推流 → `FAILED`）/ `LIVING` / `ENDED` / `FAILED`。

```powershell
$BASE = "http://localhost:9002"
$UID  = @("-H", "X-User-Id: u-2001")
$ADMIN= @("-H", "X-User-Id: u-admin", "-H", "X-User-Role: ADMIN")
$GUEST= @("-H", "X-Session-Id: sess-abc123")
```

## 3. 直播间管理

### 3.1 `POST /api/v1/live/rooms` —— 创建直播间

鉴权：必须，创建者 = `X-User-Id`。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | 1–64 字符 |
| `notice` | string | 否 | ≤ 512 字符 |
| `coverUrl` | string | 否 | ≤ 512 字符 |
| `categoryId` | int64 | 否 | 直播分区 ID（本服务自增，与商品/视频分类无关） |

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms" @UID -H "Content-Type: application/json" -d '{"title":"Go 并发实战直播","notice":"今晚 8 点开播","coverUrl":"https://cdn.example.com/c.jpg","categoryId":1}'
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "title": "Go 并发实战直播",
    "status": "IDLE",
    "streamKey": "3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "pushUrl": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "playUrls": {
      "hls": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.m3u8",
      "httpFlv": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.flv",
      "webrtc": "webrtc://localhost:8001/live/3f2a9c48b1e7d05622aa41cd9f8b7e30",
      "rtmp": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30"
    },
    "createdAt": "2026-09-27T10:00:00+08:00"
  }
}
```

> 创建时即返回 `streamKey` / `pushUrl`，它们是房间的固有属性；但**每次开播会重新生成 `streamKey`**（见 §4.1），创建时这份只在首次开播前有效，且 `pushUrl` 不带 `?session=`。

| 失败场景 | 响应 |
| --- | --- |
| 缺 `X-User-Id` | `401 {"code":40101}` |
| `title` 为空 | `400 {"code":40001,"message":"title 不能为空","data":null}` |
| 已创建 20 个房间 | `409 {"code":70003,"message":"直播间数量已达上限: 20","data":null}` |

### 3.2 `PUT /api/v1/live/rooms/:id` —— 修改

鉴权：必须，且为创建者。字段均可选，缺省/`null` 表示不修改。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `title` | string | 1–64 |
| `notice` | string | ≤ 512 |
| `coverUrl` | string | ≤ 512 |
| `categoryId` | int64 | - |

```bash
curl.exe -X PUT "$BASE/api/v1/live/rooms/5001" @UID -H "Content-Type: application/json" -d '{"title":"Go 并发实战直播（第二期）","notice":"改为 9 点"}'
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"updated":true}}
```

> `STARTING` / `LIVING` 下允许改标题与公告（运营常态），但**没有修改 `streamKey` 的入口**。

### 3.3 `DELETE /api/v1/live/rooms/:id` —— 删除

鉴权：必须，且为创建者；状态不能是 `LIVING` / `STARTING`（软删除）。

```bash
curl.exe -X DELETE "$BASE/api/v1/live/rooms/5001" @UID
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"deleted":true}}
```

直播中删除 → `409 {"code":70001,"message":"直播中不能删除直播间，请先关播","data":null}`

### 3.4 `GET /api/v1/live/rooms` —— 列表

鉴权：可选。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |

| `livingOnly` | bool | false | 等价于 `status=LIVING` |

## 4. 开播 / 关播

### 4.1 `POST /api/v1/live/rooms/:id/start` —— 开播

鉴权：必须，且为创建者。前置状态 `IDLE` / `ENDED` / `FAILED`（`STARTING` / `LIVING` 时幂等返回当前状态，不换密钥）；该主播当前不能有其他 `STARTING` / `LIVING` 的房间。

服务端生成新的 `streamKey`（32 位 hex）与 `sessionId`（16 位 hex），条件更新为 `STARTING`，写 `media_live_record`，清空 Redis 计数（`online` / `peak` / `viewers`，否则会继承上一场人数）——**不直接置 `LIVING`**（等 SRS 回调）。

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/start" @UID
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "status": "STARTING",
    "sessionId": "9c1b7d3e5f8a2b64",
    "streamKey": "3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "pushUrl": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30?session=9c1b7d3e5f8a2b64",
    "playUrls": {
      "hls": "http://localhost:8088/live/3f2a...m3u8",
      "httpFlv": "http://localhost:8088/live/3f2a....flv",
      "webrtc": "webrtc://localhost:8001/live/3f2a...",
      "rtmp": "rtmp://localhost:1936/live/3f2a..."
    },
    "srsAvailable": true,
    "startedAt": "2026-09-27T20:00:00+08:00",
    "hint": "请使用 pushUrl 推流；服务端收到 SRS on_publish 回调后状态才会变为 LIVING"
  }
}
```

| 失败场景 | 响应 |
| --- | --- |
| 已有其他正在直播的房间 | `409 {"code":70004,"message":"已有正在直播的直播间: 5002","data":null}` |
| 非创建者 | `403 {"code":40301}` |
| SRS 不可用 | `200`，但 `srsAvailable:false`（**开播仍成功**，推流时才会失败） |

**幂等**：`STARTING` 或 `LIVING` 下重复调用 → 返回当前 `streamKey` / `pushUrl` 与状态，HTTP 200，不报错、不换密钥。

### 4.2 `POST /api/v1/live/rooms/:id/stop` —— 关播

鉴权：必须，且为创建者；前置 `STARTING` / `LIVING`（其他状态幂等返回快照）。

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/stop" @UID
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"status":"ENDED","sessionId":"9c1b7d3e5f8a2b64","endedAt":"2026-09-27T22:31:05+08:00","durationSec":9065,"peakOnline":256,"viewerTotal":3421,"endReason":"manual","streamKicked":true}}
```

> `streamKicked` 表示是否成功通知 SRS 断开推流；SRS 不可达时为 `false`，但**关播本身仍成功**（主播重连会因密钥失效被拒）。

### 4.3 `POST /api/v1/live/rooms/:id/force-close` —— 强制关闭（治理）

鉴权：创建者**或** ADMIN。

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/force-close" @ADMIN -H "Content-Type: application/json" -d '{"reason":"内容违规"}'
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"status":"ENDED","endReason":"force","reason":"内容违规"}}
```

非创建者且非 ADMIN → `403 / 40301`；不在直播中 → `409 / 70001`。

## 5. 播放与在线人数

### 5.1 `GET /api/v1/live/rooms/:id/play` —— 播放地址

鉴权：可选；前置条件 `LIVING`，否则 `409 / 70001`（避免观众拉空流）。

```bash
curl.exe "$BASE/api/v1/live/rooms/5001/play"
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"title":"Go 并发实战直播","status":"LIVING","onlineCount":128,"format":["hls","httpFlv","webrtc","rtmp"],"playUrls":{"hls":"http://localhost:8088/live/3f2a...m3u8","httpFlv":"http://localhost:8088/live/3f2a....flv","webrtc":"webrtc://localhost:8001/live/3f2a...","rtmp":"rtmp://localhost:1936/live/3f2a..."}}}
```

未开播 → `409 {"code":70001,"message":"直播间当前不在直播中，状态: ENDED","data":null}`

### 5.2 `POST /api/v1/live/rooms/:id/heartbeat` —— 观众心跳

鉴权：可选（游客用 `X-Session-Id` 或请求体 `sessionId`）；建议 20 秒一次，服务端有效期 60 秒。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 游客必填 | 游客标识；已登录用户可省略 |

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/heartbeat" @UID
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/heartbeat" @GUEST -H "Content-Type: application/json" -d '{"sessionId":"sess-abc123"}'
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"onlineCount":129,"memberKey":"u:u-2001","firstEnter":false,"ttlSec":60}}
```

- `memberKey`：`u:{uid}` 或 `anon:{sessionId}`，便于前端排查「为什么我算不进去」。
- `firstEnter`：本次是否新进入（只有新进入才累加人气值 `viewerTotal`）。
- 未开播的房间心跳 → `409 / 70001`（不给人气灌水）。

### 5.3 `GET /api/v1/live/rooms/:id/online` —— 在线人数（轻量轮询）

鉴权：无。

```bash
curl.exe "$BASE/api/v1/live/rooms/5001/online"
```

```json
{"code":0,"message":"success","data":{"roomId":5001,"onlineCount":129,"peakOnline":256,"viewerTotal":3421}}
```

> 与详情接口的区别：**优先只查 Redis**（状态 Hash 过期才回源一次 MySQL），适合前端 5~10s 轮询。

## 6. SRS 回调接口（不对客户端开放）

> 网关白名单放行；不做 JWT 鉴权，靠 `streamKey`（32 位随机 hex）+ 可选的 `hook_secret` 防护。

### 6.1 `POST /api/v1/live/hooks/on-publish`

```json
{"action":"on_publish","client_id":"abc123","ip":"172.17.0.1","vhost":"__defaultVhost__","app":"live","stream":"3f2a9c48b1e7d05622aa41cd9f8b7e30","param":"?session=9c1b7d3e5f8a2b64"}
```

处理逻辑：

```text
1. app 与 media.app 不一致（SRS 未传 app 时跳过） → {"code":70002}
2. hook_secret 非空时校验 param.secret      → 不匹配则 {"code":70002}
3. 反查 streamKey（先 Redis live:key，再 MySQL）
   - 不存在 / 查询失败                      → {"code":70002}
   - session 与 current_session 不一致       → {"code":70002}（旧会话的延迟回调）
4. 状态：STARTING / ENDED → 置 LIVING，发 live.started，返回 {"code":0}
         LIVING          → 幂等返回 0（不重复发事件）
         IDLE / FAILED   → {"code":70002}
```

```bash
curl.exe -X POST "$BASE/api/v1/live/hooks/on-publish" -H "Content-Type: application/json" -d '{"action":"on_publish","app":"live","stream":"3f2a...","param":"?session=9c1b..."}'
```

```json
{"code":0,"message":"success","data":null}
```

> **SRS 只看响应体顶层 `code`**：`0` 放行，非 0 断开该流；HTTP 状态码**恒为 200**（4xx/5xx 会被当成网络故障）。

失败示例：`{"code":70002,"message":"推流密钥无效或会话已过期","data":null}`

### 6.2 `POST /api/v1/live/hooks/on-unpublish`

主播断流时由 SRS 调用，语义等同关播（`endReason=unpublish`，不断流）；密钥已失效时直接放行收尾。始终返回 `{"code":0,"message":"success","data":null}`。

### 6.3 `POST /api/v1/live/hooks/on-play` / `on-stop`

观众开始/结束播放。当前仅记日志，供后续统计使用；始终返回 `{"code":0}`。

### 6.4 本地联调用的模拟回调（仅 debug 模式注册）

```bash
curl.exe -X POST "$BASE/api/v1/live/dev/publish/3f2a9c48b1e7d05622aa41cd9f8b7e30?session=9c1b7d3e5f8a2b64"
curl.exe -X POST "$BASE/api/v1/live/dev/unpublish/3f2a9c48b1e7d05622aa41cd9f8b7e30"
```

> `APP_ENV` 非 `local/dev/debug` 时这两个路由**不会被注册**（404）。

## 8. 端到端验收脚本

```powershell
$BASE = "http://localhost:9002"; $UID = "u-2001"

# 0) 健康检查
curl.exe "$BASE/healthz"; curl.exe "$BASE/readyz"

# 1) 创建直播间
$r = curl.exe -s -X POST "$BASE/api/v1/live/rooms" -H "X-User-Id: $UID" -H "Content-Type: application/json" -d '{"title":"Go 并发实战直播","notice":"今晚 8 点"}' | ConvertFrom-Json
$rid = $r.data.roomId

# 2) 开播（拿到新的 streamKey、sessionId 与 pushUrl）
$s = curl.exe -s -X POST "$BASE/api/v1/live/rooms/$rid/start" -H "X-User-Id: $UID" | ConvertFrom-Json
$key = $s.data.streamKey; $sid = $s.data.sessionId

# 3) 有 SRS 时用 ffmpeg 推流；无 SRS 时用调试接口模拟 on_publish
curl.exe -X POST "$BASE/api/v1/live/dev/publish/$key?session=$sid"

# 4) 确认 LIVING 并取播放地址
curl.exe "$BASE/api/v1/live/rooms/$rid"; curl.exe "$BASE/api/v1/live/rooms/$rid/play"

# 5) 3 个不同用户心跳 → onlineCount 应为 3
1..3 | ForEach-Object { curl.exe -X POST "$BASE/api/v1/live/rooms/$rid/heartbeat" -H "X-User-Id: u-30$_" | Out-Null }
curl.exe "$BASE/api/v1/live/rooms/$rid/online"
```
