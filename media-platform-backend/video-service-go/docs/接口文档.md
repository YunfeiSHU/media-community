# video-service-go · 接口文档

> 服务端口 **9001** ｜ 基础路径 `/api/v1` ｜ 探针 `/healthz`、`/readyz`（不在 `/api/v1` 下）
> 契约 v1.1（含分片上传与断点续传）：**字段只增不删**。

## 1. 通用约定

### 1.1 统一响应与通用错误码

统一信封 `{code, message, data}`（`code=0` 成功，失败时 `data` 为 `null`）、HTTP 状态与错误码前缀的对应关系、时间格式
（`RFC3339`，如 `2026-09-27T10:30:00+08:00`），以及 `40001` / `40101` / `40301` / `404xx` / `409xx` / `42901` / `50000` /
`50001` 的含义见 `../../README.md` §5.1 与 §5.3；本节只补本服务的身份约定（§1.2）与域内错误码（§1.4）。

### 1.2 身份传递（与 Java 体系一致）

| 项 | 约定 |
| --- | --- |
| uid 来源 | 请求头 `X-User-Id`（网关从 JWT `sub` 注入；直连时手工携带） |
| 角色来源 | 请求头 `X-User-Role`，取值 `ADMIN` / `user`，缺失按 `user` |
| JWT | 本服务**不解析** JWT；不接受请求体 / 查询参数里的用户标识 |
| 缺身份头 | 需要登录的接口 → `401 / 40101`；非所有者或角色不足 → `403 / 40301` |
| 资源不存在 | 统一 `404 / 404xx`；**未发布且无权访问也按「不存在」返回**，不暴露存在性 |

```powershell
$BASE = "http://localhost:9001"
$UID  = @("-H", "X-User-Id: u-1001")
$ADMIN= @("-H", "X-User-Id: u-admin", "-H", "X-User-Role: ADMIN")
```

> 经网关访问时把 `$BASE` 换成 `http://localhost:8000`，并改用 `-H "Authorization: Bearer <jwt>"`；网关会自动写入
> `X-User-Id` / `X-User-Role`（先清后写，客户端伪造无效）。

### 1.3 状态枚举

- 视频：`DRAFT` 草稿（仅元数据）· `TRANSCODING` 原片已上传、转码中 · `READY` 转码完成、可发布 · `PUBLISHED` 已发布、游客可见 ·
  `OFFLINE` 已下架 · `FAILED` 转码失败。
- 转码任务：`PENDING` / `RUNNING` / `SUCCESS` / `FAILED`，`progress` 为 0–100 的整数。

### 1.4 域内错误码

| HTTP | code | 含义 |
| --- | --- | --- |
| 404 | 40401 | 视频不存在（含「未发布且非本人 / ADMIN」，不暴露存在性） |
| 404 | 40402 | 分类不存在 |
| 404 | 40403 | 转码任务不存在 |
| 404 | 40404 | 上传会话不存在或已失效（未 init / 已 complete / 已 abort） |
| 409 | 40901 | 唯一性冲突（如分类名重复） |
| 400 | 60001 | 文件类型不支持 |
| 413 | 60002 | 文件超出大小限制 |
| 409 | 60003 | 视频状态不允许该操作 |
| 503 | 60004 | 转码任务提交失败（事件投递失败，可走 retry 接口） |
| 400 | 60005 | 上传分片不合法（大小不符 / 序号越界 / partSize < 5MiB） |
| 409 | 60006 | 分片尚未全部上传（数量不足 / 序号重复 / 总大小不符） |

## 3. 视频接口

### 3.1 `POST /api/v1/videos` —— 创建视频草稿

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须（`X-User-Id`） |
| Content-Type | `application/json` |

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | 1–128 字符，去首尾空格后非空 |
| `description` | string | 否 | ≤ 1024 字符 |
| `categoryId` | int64 | 否 | 需存在，否则 `404 / 40402` |
| `tags` | string[] | 否 | ≤ 10 个、每个 ≤ 32 字符；空串丢弃、重复去重 |

**成功** `{videoId, status:"DRAFT"}`（初始状态固定为 `DRAFT`）
**失败** `401/40101` 缺身份头 · `400/40001` title 为空或超长 · `404/40402` 分类不存在

```bash
curl.exe -X POST "$BASE/api/v1/videos" @UID -H "Content-Type: application/json" `
  -d '{"title":"Go 并发编程入门","description":"goroutine 与 channel","categoryId":1,"tags":["go","并发"]}'
```

### 3.2 `GET /api/v1/videos` —— 视频列表（分页）

| 项 | 值 |
| --- | --- |
| 鉴权 | 可选（未登录只能看到 `PUBLISHED`） |

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | 从 1 开始，<1 按 1 处理 |
| `pageSize` | int | 20 | >100 按 100 处理 |
| `keyword` | string | - | 模糊匹配 `title` |
| `categoryId` | int64 | - | 精确匹配 |
| `ownerId` | string | - | 精确匹配创建者 |
| `status` | string | - | 精确匹配状态，**仅本人 / ADMIN 生效** |
| `mine` | bool | false | `true` 时只看自己的（等价 `ownerId=X-User-Id`），未登录 → `401 / 40101` |

**成功** `{total, page, pageSize, items[]}`；`items[]` 每项：`id` / `title` / `description` / `ownerId` / `categoryId` /
`categoryName` / `tags` / `coverUrl` / `duration` / `status` / `viewCount` / `publishedAt` / `createdAt` / `updatedAt`
**排序** 默认 `created_at DESC`（走 `idx_status_created` 复合索引，避免 filesort）；`page` 从 1 开始，越界返回空数组而非报错。
**规则** 非「本人 / ADMIN」的请求被强制附加 `status = PUBLISHED`；手工传 `status=DRAFT` **静默忽略**（不报错），避免信息泄露。

```bash
curl.exe "$BASE/api/v1/videos?page=1&pageSize=20&keyword=Go" @UID
```

### 3.3 `GET /api/v1/videos/:id` —— 视频详情

| 项 | 值 |
| --- | --- |
| 鉴权 | 可选 |

**成功** §3.2 的 item 全字段 + `playbackUrl`（HLS `master.m3u8` 完整 URL）/ `sizeBytes` / `sourceObject`（MinIO 对象 key）

| 字段 / 情形 | 游客 | 所有者 / ADMIN |
| --- | --- | --- |
| `sourceObject` | 不出现在响应中 | 返回 |
| 未发布视频整体 | `404 / 40401` | 正常返回 |

### 3.4 `PUT /api/v1/videos/:id` —— 修改视频

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者（ADMIN **也不能**改他人视频元数据） |
| Content-Type | `application/json` |

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `title` / `description` | string | 1–128 / ≤1024；`null` 或缺省表示不修改 |
| `categoryId` | int64 | 需存在，否则 `404 / 40402` |
| `tags` | string[] | 传数组则**整体替换**，传 `[]` 清空；规则同 §3.1 |

**成功** `{videoId, updated:true}` ｜ **失败** `403/40301` 非创建者 · `404/40401` · `400/40001` 参数不合法 · `404/40402`

```bash
curl.exe -X PUT "$BASE/api/v1/videos/1001" @UID -H "Content-Type: application/json" `
  -d '{"title":"Go 并发编程入门（第 2 版）","tags":["go","channel"]}'
```

### 3.5 `DELETE /api/v1/videos/:id` —— 删除视频（软删）

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

**成功** `{videoId, deleted:true}`。MySQL 行保留 `deleted_at`；Redis 详情缓存立即 `DEL`，MinIO 的 `video/original/{id}` 与
`video/hls/{id}` 前缀**异步**清理（清理失败不影响删除结果）。

### 3.6 `POST /api/v1/videos/:id/upload` —— 上传原片（小文件，一次传完）

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| Content-Type | `multipart/form-data` |
| 前置状态 | `DRAFT` 或 `FAILED`，否则 `409 / 60003` |
| 表单字段 | `file`（file，必填）：扩展名 ∈ `mp4,mov,mkv,avi,flv,webm`，≤ 2GB（`upload.max_size_mb=2048`） |

**成功** `{videoId, status:"TRANSCODING", taskId, sizeBytes}`（上传后视频转 `TRANSCODING`，`size_bytes`/`source_object` 落库）
**幂等** 状态已是 `TRANSCODING` → 返回 `200` 与**已有** `taskId`，不重复投递事件

| 失败场景 | 响应 |
| --- | --- |
| 扩展名不支持 | `400 {"code":60001,"message":"不支持的文件类型: exe","data":null}` |
| 超过 2GB | `413 {"code":60002,"message":"文件大小超过限制: 2048MB","data":null}` |
| 状态为 `PUBLISHED` | `409 {"code":60003,"message":"当前状态 PUBLISHED 不允许上传","data":null}` |
| 缺 `file` 字段 / 写对象存储失败 | `400 / 40001`、`503 / 50001` |

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/upload" @UID -F "file=@D:\samples\demo.mp4"
```

> 大文件（几十 MB 以上）走 §4：可并发传分片、可中断续传，不必从头重传。

### 3.7 `POST /api/v1/videos/:id/publish` —— 发布

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 前置状态 | `READY` 或 `OFFLINE`（后者即重新发布） |

**成功** `{videoId, status:"PUBLISHED", publishedAt}`（写 `published_at` 并 `DEL` 详情缓存）
**失败** `409/60003` 状态不符，或 `playback_url` 为空（「转码产物不存在，无法发布」）

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/publish" @UID
```

### 3.8 `POST /api/v1/videos/:id/offline` —— 下架

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者**或 ADMIN**（治理动作，ADMIN 可下架他人视频） |
| 前置状态 | `PUBLISHED` |

**成功** `{videoId, status:"OFFLINE"}` ｜ **失败** `403/40301` 非本人且非 ADMIN · `409/60003` 状态不允许

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/offline" @UID
curl.exe -X POST "$BASE/api/v1/videos/1001/offline" @ADMIN   # 管理员下架他人视频
```

### 3.9 `GET /api/v1/videos/:id/play` —— 获取播放信息

| 项 | 值 |
| --- | --- |
| 鉴权 | 可选（未发布视频仅本人 / ADMIN 可访问） |

**成功** `{videoId, title, coverUrl, duration, format:"hls", playbackUrl, sources[]}`；`sources[]` 每项
`{profile:"360p"|"720p"|"1080p", url, width, height, bandwidth}`，由 `media.DefaultProfiles` 推导。
**失败** 未发布且非本人 / ADMIN → `404 / 40401`；尚未转码完成 → `409 / 60003`。
每次调用都 `INCR video:view:{id}`（Redis 缓冲，**不写 MySQL**），由定时任务每 30s 批量回写。

```bash
curl.exe "$BASE/api/v1/videos/1001/play"
```

**成功** `{videoId, taskId, status, progress, profiles:["360p","720p","1080p"], message, startedAt, finishedAt}`
（`message` 为失败原因，截断到 500 字符）；`finishedAt` 在未结束时为 `null`。

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 前置状态 | `FAILED` |

**成功** `{videoId, taskId（新任务）, status:"PENDING"}`，重建任务并重新投递 `video.uploaded`。
**失败** `409/60003` 状态不是 `FAILED` · `404/40401` 视频不存在

## 4. 分片上传与断点续传

`init → parts/{n}（可并发 / 可重传）→ status（续传入口）→ complete → abort`：

```text
POST   /videos/:id/upload/init        → uploadId + 切片计划 + 已上传分片
PUT    /videos/:id/upload/parts/1     → 传第 1 片（原始二进制 application/octet-stream，可与其它片并发）
GET    /videos/:id/upload/status      → 查进度（刷新页面 / 换设备后从这里恢复）
POST   /videos/:id/upload/complete    → 合并 → TRANSCODING → 投递 video.uploaded
DELETE /videos/:id/upload             → 放弃上传，回收已传分片（会话置 ABORTED）
```

**为什么续传要经过服务端**：分片必须落在**同一次对象存储 multipart upload** 里，`complete` 才能把它们拼成一个对象；
「传到第几片」只能由对象存储侧的 `ListParts` 给出权威答案，服务端只持久化 `uploadId`（详见 `设计文档.md` §5.2）。
**客户端怎么做**：启动时调一次 `status`（或直接用 `init` 的返回），把 `uploadedParts[].partNumber` 从待传集合剔除，剩下的照常 `PUT`。

### 4.1 `POST /api/v1/videos/:id/upload/init` —— 初始化（或复用）上传会话

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| Content-Type | `application/json` |
| 前置状态 | `DRAFT` 或 `FAILED`，否则 `409 / 60003` |

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `filename` | string | 是 | 用于推断扩展名（白名单同 §3.6），必须带扩展名 |
| `fileSize` | int64 | 是 | 原片总字节数，>0 且 ≤ 2GB |
| `partSize` | int64 | 否 | 自定义分片大小（字节），不得小于 5MiB；不传由服务端推导 |

**切片大小推导规则**（`partSize` 不传时）：起点是 **5 MiB**；片数超过 **10000** 就**逐次翻倍**，直到
`ceil(fileSize / partSize) ≤ 10000`。例：11 MiB → 5 MiB/片 → 3 片；100 GiB → 20 MiB/片 → 5120 片。
**响应里的 `partSize` 是权威值**，客户端必须按它切片（可能与请求里传的不同）。

| 响应字段（`UploadSessionResult`，§4.2 / §4.3 复用） | 类型 | 说明 |
| --- | --- | --- |
| `videoId` / `uploadId` | uint64 / string | 视频 ID；对象存储侧会话 ID，后续分片请求靠它定位 |
| `objectKey` / `ext` | string | 原片 key `video/original/{id}/source.{ext}`；归一化扩展名 |
| `fileSize` / `partSize` / `totalParts` | int64 / int64 / int | 声明总字节数；分片大小（以此为准）；分片总数 |
| `uploadedParts[]` | array | 已上传分片 `{partNumber, size, etag}`，按序号升序 |
| `uploadedBytes` / `uploadedCount` / `completed` | int64 / int / bool | 已传字节合计；已传片数；是否已齐（`uploadedCount >= totalParts`） |

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/upload/init" @UID -H "Content-Type: application/json" `
  -d '{"filename":"demo.mp4","fileSize":11534336}'
```

```json
{ "code": 0, "message": "success", "data": {
    "videoId": 1001, "uploadId": "YzQxYjY...", "objectKey": "video/original/1001/source.mp4", "ext": "mp4",
    "fileSize": 11534336, "partSize": 5242880, "totalParts": 3,
    "uploadedParts": [], "uploadedBytes": 0, "uploadedCount": 0, "completed": false } }
```

**幂等** `objectKey` / `ext` / `fileSize` / `partSize`（及派生的 `totalParts`）全等、且创建未超 **24 小时** → **复用同一个
`uploadId`**，已传分片不失效；参数不一致或已超期 → 旧会话被 `abort` 后新建（避免对象存储里堆积永远合并不了的碎片）。

| 失败场景 | 响应 |
| --- | --- |
| `fileSize` ≤ 0 | `400 {"code":40001,"message":"fileSize 必须是正整数","data":null}` |
| 扩展名不在白名单 | `400 {"code":60001,"message":"不支持的文件类型: exe","data":null}` |
| `fileSize` > 2GB | `413 {"code":60002,"message":"文件大小超过限制: 2048MB","data":null}` |
| `partSize` < 5MiB | `400 {"code":60005,"message":"partSize 不得小于 5MB","data":null}` |
| 状态为 `TRANSCODING` / `PUBLISHED` | `409 {"code":60003,"message":"当前状态 TRANSCODING 不允许上传","data":null}` |
| 对象存储不可用 | `503 {"code":50001,"message":"初始化分片上传失败","data":null}` |

### 4.2 `GET /api/v1/videos/:id/upload/status` —— 查询上传进度（续传入口）

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

响应体同 §4.1；任何时候调用都能拿到 `ListParts` 的权威进度。无进行中的会话（未 `init` / 已 `complete` / 已 `abort`）→ `404 / 40404`。

```bash
curl.exe "$BASE/api/v1/videos/1001/upload/status" @UID
```

### 4.3 `PUT /api/v1/videos/:id/upload/parts/:partNumber` —— 上传单个分片

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| Content-Type | `application/octet-stream`（**原始二进制，不是 multipart 表单**） |
| 请求头 | `Content-Length` 必须显式给出（chunked 传输拿不到长度，直接报错） |

`partNumber` 从 **1** 开始、最大 `totalParts`；**成功**为 `UploadSessionResult` 全字段 + `part`（本次分片 `{partNumber,size,etag}`）。

| 分片 | 允许的大小 |
| --- | --- |
| 非末片（`partNumber < totalParts`） | **必须正好等于 `partSize`**（否则偏移量全错，问题会推迟到 `complete` 才暴露） |
| 末片（`partNumber == totalParts`） | `0 < size ≤ partSize` |

| 失败场景 | 响应 |
| --- | --- |
| 未 `init` / 会话已终结 | `404 {"code":40404,"message":"没有进行中的分片上传，请先调用 upload/init","data":null}` |
| `partNumber` 越界或 < 1 | `400 {"code":60005,"message":"partNumber 必须在 1..3 之间","data":null}` |
| 非末片大小 ≠ `partSize` | `400 {"code":60005,"message":"第 1 片大小必须为 5242880 字节","data":null}` |
| 缺 `Content-Length` | `400 {"code":60005,"message":"必须通过 Content-Length 声明分片大小","data":null}` |

```bash
curl.exe -X PUT "$BASE/api/v1/videos/1001/upload/parts/1" @UID `
  -H "Content-Type: application/octet-stream" --data-binary "@D:\samples\part-1.bin"
```

### 4.4 `POST /api/v1/videos/:id/upload/complete` —— 合并分片

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 请求体 | 无 |

服务端先校验「分片序号恰好覆盖 `1..totalParts`」且总大小相符，再合并成一个完整对象；**后续与 §3.6 完全一致**：
建转码任务 → 状态置 `TRANSCODING` → 投递 `video.uploaded`。
**成功** `{videoId, status:"TRANSCODING", taskId, sizeBytes}`；`sizeBytes` 取**合并后对象的实际大小**，而不是会话里声明的 `fileSize`。

| 失败场景 | 响应 |
| --- | --- |
| 分片没传齐 | `409 {"code":60006,"message":"已上传 2/3 片，请补齐后再合并","data":null}` |
| 分片序号重复（并发写同一片） | `409 {"code":60006,"message":"分片序号存在重复，实际覆盖 2/3 片","data":null}` |
| 总大小与声明不符 | `409 {"code":60006,"message":"分片总大小 5242880 与声明的 11534336 不一致","data":null}` |
| 无进行中的会话 | `404 / 40404` |
| 合并失败 / 对象存储不可用 | `503 {"code":50001,"message":"合并分片失败","data":null}` |

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/upload/complete" @UID
```

### 4.5 `DELETE /api/v1/videos/:id/upload` —— 取消上传

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

中止对象存储侧的 multipart upload 并**回收已上传的分片**，会话置 `ABORTED`。**成功** `{videoId, aborted:true}`；
无进行中的会话 → `404 / 40404`。取消后 `status` 与 `parts` 都返回 `40404`，想重传必须重新 `init`（会得到新的 `uploadId`）。

### 4.6 并发与竞态

| 场景 | 行为 |
| --- | --- |
| 并发 `PUT` 同一个 `partNumber` | 对象存储以最后一次写入为准（同一片被覆盖），`complete` 的「序号集合」校验能挡住由此产生的重复/缺失 |
| 同一视频存在多条 `UPLOADING` 会话（进程崩溃等） | 取最新一条，其余 `abort` 回收，保证「同一视频同一时间只有一个可用 `uploadId`」 |
| 合并与 `abort` 并发 | 先到者生效，后到者拿到 `404 / 40404` 或 `503 / 50001`（合并失败），客户端应重新 `init` |
| 客户端边传边刷新 | `status` 只读 `ListParts`，不存在本地进度副本，因此任何时候查到的都是真实进度 |
