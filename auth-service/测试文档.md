# Auth Service 测试文档

## 1. 测试目的

验证手机号/邮箱认证、验证码、JWT、Redis Session、Refresh Token Rotation、退出登录、强制下线和登录限流是否符合技术方案与代码实现。

本次测试重点判断：

- 验证码生成、发送冷却、Redis TTL 和一次性校验是否正确
- 手机号/邮箱登录和注册业务是否正确
- 登录是否返回 Access Token 和 Refresh Token
- JWT 是否正确写入并签名 `sub`、`iat`、`exp`
- Refresh Token Rotation 是否返回新 Token，并拒绝无效或格式错误的旧 Token
- HTTP 接口是否返回预期的状态码、业务码、消息和 JSON 数据
- Controller 调用的 Service 方法是否按预期执行
- 退出登录和强制下线是否正确处理 Access Token 黑名单与 Redis Session
- 登录接口是否按 IP 执行固定窗口限流，超过 5 次后返回预期错误
- Spring Boot、MySQL、Redis 客户端 Bean 是否可以正常加载

## 5. 需求正确性判断

### 5.1 已确认正确的需求

根据本次实际测试结果，以下需求在当前单元测试范围内实现正确：

1. 手机号和邮箱目标标准化及格式校验
2. 验证码 6 位数字生成
3. 验证码 180 秒 TTL 和发送冷却 60 秒
4. 验证码校验成功后删除 Redis Key
5. 登录密码错误时不生成 Token、不创建 Session
6. 登录成功返回 Access Token 和 Refresh Token
7. JWT 使用 uid 作为 `sub`，包含签发时间和过期时间
8. Refresh Token Rotation 返回新 Refresh Token
9. Rotation 失败时拒绝刷新
10. 非法 Refresh Token 格式在访问 Redis 前被拒绝
11. Spring Boot 上下文、MySQL 数据源和相关 Bean 正常启动
12. 登录接口按 IP 进行 60 秒固定窗口限流，超过 60 次拒绝请求
13. 限流首次请求设置 TTL，窗口内后续请求不重置 TTL

### 5.2 当前尚未完全证明的部分

以下结论不能仅通过当前 Mockito 单元测试确认：

1. **Redis 高并发 Rotation**：当前已验证单次真实 Rotation 和旧 Token 失效；同一旧 Token 的高并发竞争仍可增加压力测试。
2. **Access Token 业务鉴权过滤器**：当前项目已生成 jti 并提供黑名单查询方法，但尚未测试带 Bearer Token 访问受保护接口时的完整验签和黑名单拦截流程。
3. **Redis 不可用时的错误响应**：Redis 连接拒绝时当前可能返回 HTTP 500，尚未转换为统一业务错误响应。
4. **真实环境网络与代理配置**：Testcontainers 依赖 Docker 镜像仓库，CI 环境仍需单独配置 Docker、镜像缓存或代理。
