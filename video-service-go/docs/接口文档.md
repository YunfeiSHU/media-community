# video-service-go · 接口文档

> 服务端口：**9001** ｜ 基础路径：`/api/v1` ｜ 健康检查：`/healthz`、`/readyz`
> 契约版本：**v1.1**（阶段一，含分片上传与断点续传）。字段一旦发布不再删除，只做新增。

## 1. 通用约定

### 1.1 统一响应体

```json
{ "code": 0, "message": "success", "data": { } }
```

- `code = 0` 成功，其它见 §1.4。
- 失败时 `data` 为 `null`。
- 时间格式 `RFC3339`（`2026-09-27T10:30:00+08:00`）。

### 1.2 身份传递（与 Java 体系一致）

| 项 | 约定 |
| --- | --- |
| uid 来源 | 请求头 `X-User-Id`（网关从 JWT `sub` 注入；直连时手工携带） |
| 角色来源 | 请求头 `X-User-Role`，取值 `ADMIN` / `user`，缺失按 `user` |
| JWT | 本服务**不解析** JWT；不接受请求体 / 查询参数里的用户标识 |
| 缺身份头 | 需要登录的接口返回 `401 / 40101` |
| 非法资源访问 | `403 / 40301` |

```powershell
$BASE = "http://localhost:9001"
$UID  = @("-H", "X-User-Id: u-1001")
$ADMIN= @("-H", "X-User-Id: u-admin", "-H", "X-User-Role: ADMIN")
```

> 经网关访问时把 `$BASE` 换成 `http://localhost:8000`，并改用
> `-H "Authorization: Bearer <jwt>"`；网关会自动写入 `X-User-Id` / `X-User-Role`。

### 1.3 状态枚举

| 值 | 含义 |
| --- | --- |
| `DRAFT` | 草稿，仅有元数据，未上传原片 |
| `TRANSCODING` | 原片已上传，转码中 |
| `READY` | 转码完成，可发布 |
| `PUBLISHED` | 已发布，游客可见 |
| `OFFLINE` | 已下架 |
| `FAILED` | 转码失败 |

转码任务状态：`PENDING` / `RUNNING` / `SUCCESS` / `FAILED`

### 1.4 错误码

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | 40001 | 请求参数不合法 |
| 400 | 60001 | 文件类型不支持 |
| 401 | 40101 | 未认证（缺 `X-User-Id`） |
| 403 | 40301 | 无权限 / 非视频创建者 |
| 404 | 40401 | 视频不存在 |
| 404 | 40402 | 分类不存在 |
| 404 | 40403 | 转码任务不存在 |
| 404 | 40404 | 上传会话不存在或已失效（未 init / 已 complete / 已 abort） |
| 409 | 40901 | 唯一性冲突（如分类名重复） |
| 409 | 60003 | 视频状态不允许该操作 |
| 413 | 60002 | 文件超出大小限制 |
| 429 | 42901 | 请求过于频繁 |
| 500 | 50000 | 内部错误 |
| 503 | 50001 | 下游依赖不可用（MySQL/Redis/MQ/MinIO） |
| 503 | 60004 | 转码任务提交失败 |
| 400 | 60005 | 上传分片不合法（大小不符 / 序号越界 / partSize 小于 5MiB） |
| 409 | 60006 | 分片尚未全部上传（数量不足 / 序号重复 / 总大小不符） |

## 2. 健康检查

### 2.1 `GET /healthz` —— 存活探针

不检查任何下游依赖，仅表示进程存活。用于 K8s `livenessProbe`。

```bash
curl.exe http://localhost:9001/healthz
```

```json
{ "code": 0, "message": "success", "data": { "status": "UP", "service": "video-service", "version": "v1.0.0" } }
```

### 2.2 `GET /readyz` —— 就绪探针

逐项检查 MySQL / Redis / 事件总线 / MinIO，任一失败返回 `503 / 50001`。

```bash
curl.exe http://localhost:9001/readyz
```

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "UP",
    "checks": [
      { "name": "mysql",   "status": "UP", "latencyMs": 3,  "detail": "" },
      { "name": "redis",   "status": "UP", "latencyMs": 1,  "detail": "" },

    ]
  }
}
```

## 3. 视频接口

### 3.1 `POST /api/v1/videos` —— 创建视频草稿

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须（`X-User-Id`） |
| Content-Type | `application/json` |

**请求体**

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | 1–128 字符 |
| `description` | string | 否 | ≤ 1024 字符 |
| `categoryId` | int64 | 否 | 需存在，否则 `404 / 40402` |
| `tags` | string[] | 否 | 每个 ≤ 32 字符，最多 10 个 |

```bash
curl.exe -X POST "$BASE/api/v1/videos" @UID `
  -H "Content-Type: application/json" `
  -d '{"title":"Go 并发编程入门","description":"goroutine 与 channel","categoryId":1,"tags":["go","并发"]}'
```

```json
{ "code": 0, "message": "success", "data": { "videoId": 1001, "status": "DRAFT" } }
```

**失败**

| 场景 | 响应 |
| --- | --- |
| 缺 `X-User-Id` | `401 {"code":40101,"message":"未登录或登录已过期","data":null}` |
| `title` 为空 | `400 {"code":40001,"message":"title 不能为空","data":null}` |
| `categoryId` 不存在 | `404 {"code":40402,"message":"分类不存在","data":null}` |

| 项 | 值 |

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

| 前置状态 | `DRAFT` 或 `FAILED`，否则 `409 / 60003` |

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

```bash

  -F "file=@D:\samples\demo.mp4"
```

```json

  "code": 0, "message": "success",
  "data": { "videoId": 1001, "status": "TRANSCODING", "taskId": 9, "sizeBytes": 10485760 }
}
```

**失败**

| 场景 | 响应 |
| --- | --- |
| 扩展名 `exe` | `400 {"code":60001,"message":"不支持的文件类型: exe","data":null}` |

## 4. 分片上传与断点续传

> **什么时候用**：原片较大（几十 MB 以上）时用这一组接口；
> 小文件用 §3.6 的一次性上传即可，一次请求搞定。

### 4.0 交互流程与断点续传原理

```text
POST   /videos/:id/upload/init        → uploadId + 切片计划 + 已上传分片
PUT    /videos/:id/upload/parts/1     → 传第 1 片（原始二进制 application/octet-stream）
PUT    /videos/:id/upload/parts/2     → 传第 2 片（可与 part#1 并发）
GET    /videos/:id/upload/status      → 查进度（刷新页面 / 换设备后从这里恢复）
PUT    /videos/:id/upload/parts/N     → 传末片
POST   /videos/:id/upload/complete    → 合并 → TRANSCODING → 投递 video.uploaded
DELETE /videos/:id/upload             → 放弃上传，回收已传分片
```

**为什么断点续传要经过服务端**：分片必须落在**同一次对象存储 multipart upload** 里，
`complete` 才能把它们拼成一个对象。所以「传到第几片」这件事只能由服务端
（准确地说：对象存储侧的 `ListParts`）给出权威答案 —— 客户端本地记什么都不足为凭，
服务端也不另存一份进度（另存必然漂移）。

**客户端怎么做断点续传**：启动时调一次 `status`（或直接用 `init` 的返回），
把 `uploadedParts[].partNumber` 从「待传集合」里剔除，剩下的照常 `PUT`。

### 4.1 `POST /api/v1/videos/:id/upload/init` —— 初始化分片上传

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| Content-Type | `application/json` |
| 前置状态 | `DRAFT` 或 `FAILED`，否则 `409 / 60003` |

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `filename` | string | 是 | 用于推断扩展名（同 §3.6 的白名单） |
| `fileSize` | int64 | 是 | 原片总字节数，> 0 且 ≤ 2GB |
| `partSize` | int64 | 否 | 自定义分片大小（字节）。不传由服务端推导；传了必须 ≥ 5MiB |

**分片大小推导规则**（`partSize` 不传时）

1. 下限是 **5MiB**（S3 协议对非末片的硬要求，小于它 `complete` 会被对象存储拒绝）；
2. 依次翻倍，直到 `ceil(fileSize / partSize) ≤ 10000`。

例：11MiB → 5MiB/片 → 3 片（5 + 5 + 1）；100GiB → 20MiB/片 → 5120 片。

**响应**（`UploadSessionResult`，§4.2 / §4.3 也用这个结构）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `videoId` | uint64 | 视频 ID |
| `uploadId` | string | 对象存储侧的会话 ID，后续分片请求都靠它定位 |
| `objectKey` | string | 原片在对象存储中的 key（`video/original/{id}/source.{ext}`） |
| `ext` | string | 归一化后的扩展名 |
| `fileSize` | int64 | 本次会话声明的总字节数 |
| `partSize` | int64 | 分片大小，**以这个值为准**（可能与请求里传的不同） |
| `totalParts` | int | 分片总数 |
| `uploadedParts` | array | 已上传分片 `[{partNumber,size,etag}]`，按序号升序 |
| `uploadedBytes` | int64 | 已上传字节合计 |
| `uploadedCount` | int | 已上传分片数 |
| `completed` | bool | 是否已齐（`uploadedCount >= totalParts`） |

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/upload/init" @UID \
  -H "Content-Type: application/json" \
  -d '{"filename":"demo.mp4","fileSize":11534336}'
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "videoId": 1001, "uploadId": "YzQxYjY...",
    "objectKey": "video/original/1001/source.mp4", "ext": "mp4",
    "fileSize": 11534336, "partSize": 5242880, "totalParts": 3,
    "uploadedParts": [], "uploadedBytes": 0, "uploadedCount": 0, "completed": false
  }
}
```

**幂等**：同参数（`objectKey` / `ext` / `fileSize` / `partSize` / `totalParts` 全等，
且创建未超 24 小时）重复调用会**复用同一个 `uploadId`**，已上传的分片不会失效。
参数不一致或已超 24 小时 → 旧会话被 `abort` 并新建
（避免对象存储里堆积永远合并不了的碎片）。

**失败**

| 场景 | 响应 |
| --- | --- |
| `fileSize` ≤ 0 | `400 {"code":40001,"message":"fileSize 必须是正整数","data":null}` |
| 扩展名不在白名单 | `400 {"code":60001,"message":"不支持的文件类型: exe","data":null}` |
| `fileSize` > 2GB | `413 {"code":60002,"message":"文件大小超过限制: 2048MB","data":null}` |
| `partSize` < 5MiB | `400 {"code":60005,"message":"partSize 不得小于 5MB","data":null}` |
| 状态为 `TRANSCODING` / `PUBLISHED` | `409 {"code":60003,"message":"当前状态 TRANSCODING 不允许上传","data":null}` |
| 对象存储不可用 | `503 {"code":50001,"message":"初始化分片上传失败","data":null}` |

### 4.2 `GET /api/v1/videos/:id/upload/status` —— 查询上传进度

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

返回体同 §4.1；**这是断点续传的入口**，任何时候调用都能拿到权威进度。
没有进行中的会话 → `404 / 40404`（已 `complete`、已 `abort`、或从未 `init`）。

```bash
curl.exe "$BASE/api/v1/videos/1001/upload/status" @UID
```

### 4.3 `PUT /api/v1/videos/:id/upload/parts/:partNumber` —— 上传分片

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| Content-Type | `application/octet-stream`（**原始二进制，不是 multipart 表单**） |
| 请求头 | `Content-Length` 必须显式给出 |

`partNumber` 从 **1** 开始，最大为 `totalParts`。分片大小规则：

| 分片 | 允许的大小 |
| --- | --- |
| 非末片（`partNumber < totalParts`） | **必须正好等于 `partSize`** |
| 末片（`partNumber == totalParts`） | `0 < size ≤ partSize` |

> 为什么非末片要求严格相等：分片边界在 `init` 时就已算好并写进会话，
> 客户端擅自改大小会让 `totalParts` 与实际不符，问题会推迟到 `complete` 才暴露，
> 排查成本高得多。宁可在这里立刻报错。

**响应**：`UploadSessionResult` 全字段 + `part`（本次上传的分片 `{partNumber,size,etag}`）。

```bash
curl.exe -X PUT "$BASE/api/v1/videos/1001/upload/parts/1" @UID \
  -H "Content-Type: application/octet-stream" \
  --data-binary "@D:\samples\part-1.bin"
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "videoId": 1001, "uploadId": "YzQxYjY...", "partSize": 5242880, "totalParts": 3,
    "uploadedParts": [ { "partNumber": 1, "size": 5242880, "etag": "0f1c..." } ],
    "uploadedBytes": 5242880, "uploadedCount": 1, "completed": false,
    "part": { "partNumber": 1, "size": 5242880, "etag": "0f1c..." }
  }
}
```

**失败**

| 场景 | 响应 |
| --- | --- |
| 未 `init` / 会话已终结 | `404 {"code":40404,"message":"没有进行中的分片上传，请先调用 upload/init","data":null}` |
| `partNumber` 越界或 < 1 | `400 {"code":60005,"message":"partNumber 必须在 1..3 之间","data":null}` |
| 非末片大小 ≠ `partSize` | `400 {"code":60005,"message":"第 1 片大小必须为 5242880 字节","data":null}` |
| 缺 `Content-Length` | `400 {"code":60005,"message":"必须通过 Content-Length 声明分片大小","data":null}` |

### 4.4 `POST /api/v1/videos/:id/upload/complete` —— 合并分片

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

无需请求体。服务端会先校验「分片是否正好覆盖 `1..totalParts` 且总大小相符」，
再合并成一个完整对象；**后续与 §3.6 完全一致**：
建转码任务 → 状态置 `TRANSCODING` → 投递 `video.uploaded`。

响应与 §3.6 相同（`videoId` / `status` / `taskId` / `sizeBytes`）。
注意 `sizeBytes` 取**合并后对象的实际大小**，而不是会话里声明的 `fileSize`。

```bash
curl.exe -X POST "$BASE/api/v1/videos/1001/upload/complete" @UID
```

```json
{ "code": 0, "message": "success", "data": { "videoId": 1001, "status": "TRANSCODING", "taskId": 9, "sizeBytes": 11534336 } }
```

**失败**

| 场景 | 响应 |
| --- | --- |
| 分片没传齐 | `409 {"code":60006,"message":"已上传 2/3 片，请补齐后再合并","data":null}` |
| 分片序号重复（并发写同一片） | `409 {"code":60006,"message":"分片序号存在重复，实际覆盖 2/3 片","data":null}` |
| 总大小与声明不符 | `409 {"code":60006,"message":"分片总大小 5242880 与声明的 11534336 不一致","data":null}` |
| 无进行中的会话 | `404 {"code":40404,...}` |
| 合并失败 / 对象存储不可用 | `503 {"code":50001,"message":"合并分片失败","data":null}` |

### 4.5 `DELETE /api/v1/videos/:id/upload` —— 取消上传

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

中止对象存储侧的 multipart upload 并**回收已上传的分片**，会话置 `ABORTED`。

```json
{ "code": 0, "message": "success", "data": { "videoId": 1001, "aborted": true } }
```

没有进行中的会话 → `404 / 40404`。

> 取消后 `status` / `parts` 都会返回 `40404`；想重传必须重新 `init`（会得到新的 `uploadId`）。

### 4.6 完整示例（含断点续传）

```powershell
$BASE = "http://localhost:9001"
$UID  = @("-H", "X-User-Id: u-1001")
$vid  = 1001
$src  = "D:\samples\demo.mp4"
$size = (Get-Item $src).Length

# 1) init（同参数重复调用是安全的，会复用同一 uploadId）
$s = curl.exe -s -X POST "$BASE/api/v1/videos/$vid/upload/init" @UID `
  -H "Content-Type: application/json" `
  -d ('{"filename":"demo.mp4","fileSize":' + $size + '}') | ConvertFrom-Json
$partSize = $s.data.partSize      # 以服务端返回的为准，别用本地推算的值
$total    = $s.data.totalParts
$done     = @($s.data.uploadedParts | ForEach-Object { $_.partNumber })
"uploadId=$($s.data.uploadId) partSize=$partSize total=$total 已传=$($done -join ',')"

# 2) 续传：跳过已上传的分片
$all = [System.IO.File]::ReadAllBytes($src)
for ($no = 1; $no -le $total; $no++) {
  if ($done -contains $no) { continue }
  $off = ($no - 1) * $partSize
  $len = [Math]::Min($partSize, $size - $off)
  $buf = New-Object byte[] $len
  [Array]::Copy($all, $off, $buf, 0, $len)
  $tmp = Join-Path $env:TEMP "part-$no.bin"
  [System.IO.File]::WriteAllBytes($tmp, $buf)
  curl.exe -s -X PUT "$BASE/api/v1/videos/$vid/upload/parts/$no" @UID `
    -H "Content-Type: application/octet-stream" --data-binary "@$tmp" | Out-Null
  Remove-Item $tmp -Force
}

# 3) 合并
curl.exe -s -X POST "$BASE/api/v1/videos/$vid/upload/complete" @UID

# 4) 放弃上传（可选）
# curl.exe -s -X DELETE "$BASE/api/v1/videos/$vid/upload" @UID
```

> 完整可重复运行的验收脚本见 `tools/upload-chunk-smoke.ps1`（49 项断言）。

## 6. 端到端验收脚本

```powershell
$BASE = "http://localhost:9001"
$UID  = "u-1001"

# 0) 健康检查
curl.exe "$BASE/healthz"
curl.exe "$BASE/readyz"

# 1) 创建草稿
$r = curl.exe -s -X POST "$BASE/api/v1/videos" `
  -H "X-User-Id: $UID" -H "Content-Type: application/json" `
  -d '{"title":"Go 并发编程入门","description":"demo","tags":["go"]}' | ConvertFrom-Json
$vid = $r.data.videoId
"videoId = $vid"

# 2) 上传原片（准备一个任意 mp4；mock 转码器不会真正解析内容）
curl.exe -X POST "$BASE/api/v1/videos/$vid/upload" -H "X-User-Id: $UID" -F "file=@D:\samples\demo.mp4"

# 3) 轮询转码（mock 驱动会在数秒内完成）
1..10 | ForEach-Object {
  Start-Sleep -Seconds 2
  $t = curl.exe -s "$BASE/api/v1/videos/$vid/transcode" -H "X-User-Id: $UID" | ConvertFrom-Json
  "task status = $($t.data.status) progress = $($t.data.progress)"
  if ($t.data.status -eq "SUCCESS") { break }
}

# 4) 发布
curl.exe -X POST "$BASE/api/v1/videos/$vid/publish" -H "X-User-Id: $UID"

# 5) 取播放地址（游客身份）
curl.exe "$BASE/api/v1/videos/$vid/play"

# 6) 越权校验：他人修改应 403
curl.exe -X PUT "$BASE/api/v1/videos/$vid" -H "X-User-Id: u-9999" `
  -H "Content-Type: application/json" -d '{"title":"hack"}'
```

> `Start-Sleep` 仅用于演示轮询；真实调用中建议由前端按 `Retry-After` 或固定 2s 间隔轮询。

分片上传与断点续传有独立的验收脚本 **`tools/upload-chunk-smoke.ps1`**（49 项断言），
覆盖：init 切片计划推导 / 不合法分片 / 断点续传查进度 / 重复 init 幂等复用 /
分片未齐拒绝合并 / 合并并转码到 READY / abort 回收 / 权限与参数校验。
