# live-service-go · 接口文档

> 服务端口：**9002** ｜ 基础路径：`/api/v1` ｜ 健康检查：`/healthz`、`/readyz`
> 契约定稿：v1.0（阶段一）
> 另有一组 **SRS 回调接口**（`/api/v1/live/hooks/*`）不对客户端开放，见 §6。

---

## 1. 通用约定

### 1.1 统一响应体

```json
{ "code": 0, "message": "success", "data": { } }
```

### 1.2 身份传递（与 Java 体系一致）

| 项 | 约定 |
| --- | --- |
| uid 来源 | 请求头 `X-User-Id` |
| 角色来源 | 请求头 `X-User-Role`（`ADMIN` / `user`） |
| 游客会话 | 请求头 `X-Session-Id`（可选，用于游客上报心跳；缺失时服务端按 IP+UA 兜底） |
| 缺身份头 | 需要登录的接口 → `401 / 40101` |
| 非房间创建者 | `403 / 40301` |

```powershell
$BASE = "http://localhost:9002"
$UID  = @("-H", "X-User-Id: u-2001")
$ADMIN= @("-H", "X-User-Id: u-admin", "-H", "X-User-Role: ADMIN")
$GUEST= @("-H", "X-Session-Id: sess-abc123")
```

### 1.3 状态枚举

直播间状态：`IDLE` / `STARTING` / `LIVING` / `ENDED` / `FAILED`

| 值 | 含义 |
| --- | --- |
| `IDLE` | 已创建，从未开播 |
| `STARTING` | 已下发推流地址，等待推流（60s 未推流 → `FAILED`） |
| `LIVING` | 正在直播 |
| `ENDED` | 直播结束 |
| `FAILED` | 开播失败 |

### 1.4 错误码

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | 40001 | 请求参数不合法 |
| 401 | 40101 | 未认证（缺 `X-User-Id`） |
| 403 | 40301 | 无权限 / 非直播间创建者 |
| 404 | 70005 | 直播间不存在 |
| 409 | 70001 | 直播间不在直播中 |
| 409 | 70002 | 推流密钥无效 / 会话不匹配 |
| 409 | 70003 | 直播间数量超出限制 |
| 409 | 70004 | 已有正在直播的直播间 |
| 429 | 42901 | 请求过于频繁 |
| 500 | 50000 | 内部错误 |
| 503 | 50001 | 下游依赖不可用 |
| 503 | 70006 | 媒体服务（SRS）不可用 |

## 2. 健康检查

### 2.1 `GET /healthz`

```bash
curl.exe http://localhost:9002/healthz
```

```json
{ "code": 0, "message": "success", "data": { "status": "UP", "service": "live-service", "version": "v1.0.0" } }
```

### 2.2 `GET /readyz`

检查 MySQL / Redis / 事件总线 / 媒体服务，任一失败 → `503 / 50001`。

```json
{
  "code": 0, "message": "success",
  "data": {
    "status": "UP",
    "checks": [
      { "name": "mysql",  "status": "UP", "latencyMs": 2,  "detail": "ok" },
      { "name": "redis",  "status": "UP", "latencyMs": 1,  "detail": "ok" },
      { "name": "events", "status": "UP", "latencyMs": 0,  "detail": "driver=rabbitmq" },
      { "name": "srs",    "status": "UP", "latencyMs": 8,  "detail": "driver=mock" }
    ]
  }
}
```

> `media.driver=mock` 时 `srs` 一项恒为 `UP`（detail 标注 `driver=mock`），
> 避免本地无 SRS 时 `/readyz` 永远红。

## 3. 直播间管理

### 3.1 `POST /api/v1/live/rooms` —— 创建直播间

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须 |

**请求体**

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | 1–64 字符 |
| `notice` | string | 否 | ≤ 512 字符 |
| `coverUrl` | string | 否 | ≤ 512 字符 |
| `categoryId` | int64 | 否 | 直播分区 ID（本服务内自增，与商品/视频分类无关） |

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms" @UID `
  -H "Content-Type: application/json" `
  -d '{"title":"Go 并发实战直播","notice":"今晚 8 点开播","coverUrl":"https://cdn.example.com/c.jpg","categoryId":1}'
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "title": "Go 并发实战直播",
    "status": "IDLE",
    "streamKey": "3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "pushUrl": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "playUrls": {
      "hls": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.m3u8",
      "httpFlv": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.flv",
      "webrtc": "webrtc://localhost:8001/live/3f2a9c48b1e7d05622aa41cd9f8b7e30",
      "rtmp": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30"
    },
    "createdAt": "2026-09-27T10:00:00+08:00"
  }
}
```

> **创建时即返回 `streamKey` / `pushUrl`**，因为它们是房间的固有属性。
> 但**每次开播会重新生成 `streamKey`**（见 §4.1），因此创建时拿到的那份只在首次开播前有效。

**失败**

| 场景 | 响应 |
| --- | --- |
| 缺 `X-User-Id` | `401 {"code":40101,...}` |
| `title` 为空 | `400 {"code":40001,"message":"title 不能为空","data":null}` |
| 已创建 20 个房间 | `409 {"code":70003,"message":"直播间数量已达上限: 20","data":null}` |

### 3.2 `PUT /api/v1/live/rooms/:id` —— 修改直播间

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |

**请求体**（字段均可选，`null`/缺省表示不修改）

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `title` | string | 1–64 |
| `notice` | string | ≤ 512 |
| `coverUrl` | string | ≤ 512 |
| `categoryId` | int64 | - |

```bash
curl.exe -X PUT "$BASE/api/v1/live/rooms/5001" @UID `
  -H "Content-Type: application/json" `
  -d '{"title":"Go 并发实战直播（第二期）","notice":"改为 9 点"}'
```

```json
{ "code": 0, "message": "success", "data": { "roomId": 5001, "updated": true } }
```

> 直播中（`STARTING`/`LIVING`）允许改标题与公告 —— 这是运营常态；
> 但**不允许改 `streamKey`**（无此字段入口）。

### 3.3 `DELETE /api/v1/live/rooms/:id` —— 删除直播间

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 前置条件 | 状态不是 `LIVING` / `STARTING` |

```bash
curl.exe -X DELETE "$BASE/api/v1/live/rooms/5001" @UID
```

```json
{ "code": 0, "message": "success", "data": { "roomId": 5001, "deleted": true } }
```

直播中删除 → `409 {"code":70001,"message":"直播中不能删除直播间，请先关播","data":null}`

### 3.4 `GET /api/v1/live/rooms` —— 直播间列表

| 项 | 值 |
| --- | --- |
| 鉴权 | 可选 |

**查询参数**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | - |
| `pageSize` | int | 20 | 1–100 |
| `keyword` | string | - | 模糊匹配 `title` |

## 4. 开播 / 关播

### 4.1 `POST /api/v1/live/rooms/:id/start` —— 开播

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 前置状态 | `IDLE` / `ENDED` / `FAILED`（`STARTING`/`LIVING` 时幂等返回） |
| 附加约束 | 该主播当前没有正在直播的房间 |

**服务端行为**：生成新的 `streamKey` 与 `sessionId`，状态置 `STARTING`，
写一条 `media_live_record`，初始化 Redis 计数；**不直接置 `LIVING`**（等 SRS 回调）。

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/start" @UID
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "status": "STARTING",
    "sessionId": "9c1b7d3e5f8a2b64",
    "streamKey": "3f2a9c48b1e7d05622aa41cd9f8b7e30",
    "pushUrl": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30?session=9c1b7d3e5f8a2b64",
    "playUrls": {
      "hls": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.m3u8",
      "httpFlv": "http://localhost:8088/live/3f2a9c48b1e7d05622aa41cd9f8b7e30.flv",
      "webrtc": "webrtc://localhost:8001/live/3f2a9c48b1e7d05622aa41cd9f8b7e30",
      "rtmp": "rtmp://localhost:1936/live/3f2a9c48b1e7d05622aa41cd9f8b7e30"
    },
    "srsAvailable": true,
    "startedAt": "2026-09-27T20:00:00+08:00",
    "hint": "请使用 pushUrl 推流；服务端收到 SRS on_publish 回调后状态才会变为 LIVING"
  }
}
```

**失败**

| 场景 | 响应 |
| --- | --- |
| 已有其他正在直播的房间 | `409 {"code":70004,"message":"已有正在直播的直播间: 5002","data":null}` |
| 非创建者 | `403 {"code":40301,...}` |
| SRS 不可用 | `200`，但 `srsAvailable:false`（**开播仍成功**，主播推流时才会失败） |

**幂等**：`STARTING` 或 `LIVING` 状态下重复调用 → 返回当前 `streamKey`/`pushUrl` 与
`status`，HTTP 200，不报错、不换密钥。

### 4.2 `POST /api/v1/live/rooms/:id/stop` —— 关播

| 项 | 值 |
| --- | --- |
| 鉴权 | 必须，且为创建者 |
| 前置状态 | `STARTING` / `LIVING`（其他状态幂等返回） |

```bash
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/stop" @UID
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "status": "ENDED",
    "sessionId": "9c1b7d3e5f8a2b64",
    "endedAt": "2026-09-27T22:31:05+08:00",
    "durationSec": 9065,
    "peakOnline": 256,
    "viewerTotal": 3421,
    "endReason": "manual",
    "streamKicked": true
  }
}
```

> `streamKicked` 表示是否成功通知 SRS 断开推流。SRS 不可达时为 `false`，
> 但**关播本身仍然成功**（主播的流会因密钥失效在下次重连时被拒）。

### 5.2 `POST /api/v1/live/rooms/:id/heartbeat` —— 观众心跳

| 项 | 值 |
| --- | --- |
| 鉴权 | 可选（游客用 `X-Session-Id`，或请求体传 `sessionId`） |
| 建议频率 | 20 秒一次；服务端有效期 60 秒 |

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 游客必填 | 游客标识；已登录用户可省略 |

```bash
# 登录用户
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/heartbeat" @UID

# 游客
curl.exe -X POST "$BASE/api/v1/live/rooms/5001/heartbeat" @GUEST `
  -H "Content-Type: application/json" -d '{"sessionId":"sess-abc123"}'
```

```json
{
  "code": 0, "message": "success",
  "data": {
    "roomId": 5001,
    "onlineCount": 129,
    "memberKey": "u:u-2001",
    "firstEnter": false,
    "ttlSec": 60
  }
}
```

- `memberKey`：`u:{uid}` 或 `anon:{sessionId}`，便于前端排查「为什么我算不进去」。
- `firstEnter`：本次是否为新进入（影响人气值累加）。
- 未开播的房间心跳请求 → `409 / 70001`（不给人气灌水）。

## 6. SRS 回调接口（不对客户端开放）

> 网关白名单放行；不做 JWT 鉴权，靠 `streamKey`（32 位随机 hex）+ 可选 `hook_secret` 防护。
> 返回非 `0` 的 `code` 会让 SRS 拒绝/断开该流。

### 6.1 `POST /api/v1/live/hooks/on-publish`

**SRS 请求体（关键字段）**

```json
{
  "action": "on_publish",
  "client_id": "abc123",
  "ip": "172.17.0.1",
  "vhost": "__defaultVhost__",
  "app": "live",
  "stream": "3f2a9c48b1e7d05622aa41cd9f8b7e30",
  "param": "?session=9c1b7d3e5f8a2b64"
}
```

**处理逻辑**

```text
1. app != 配置的 media.app                 → 返回 {"code":70002}
2. 可用 hook_secret 时校验 query 中的 secret → 不匹配则 {"code":70002}
3. Redis/MySQL 反查 streamKey
   - 不存在                                → {"code":70002}
   - session 与当前会话不一致                → {"code":70002}（旧会话的延迟回调）
4. 房间状态
   - STARTING  → 置 LIVING，发 live.started，返回 {"code":0}
   - LIVING    → 幂等，返回 {"code":0}（不重复发事件）
   - ENDED     → 视为新一轮：置 LIVING（兼容 SRS 断线重推）
5. 其他状态（IDLE/FAILED）                   → {"code":70002}
```

```bash
curl.exe -X POST "$BASE/api/v1/live/hooks/on-publish" `
  -H "Content-Type: application/json" `
  -d '{"action":"on_publish","app":"live","stream":"3f2a...","param":"?session=9c1b..."}'
```

```json
{ "code": 0, "message": "success", "data": null }
```

**失败示例**

```json
{ "code": 70002, "message": "推流密钥无效或会话已过期", "data": null }
```

### 6.2 `POST /api/v1/live/hooks/on-unpublish`

主播断流时由 SRS 调用，语义等同关播，`endReason=unpublish`。

```json
{ "code": 0, "message": "success", "data": null }
```

### 6.3 `POST /api/v1/live/hooks/on-play` / `on-stop`

观众开始/结束播放。当前仅记日志与计数器，供后续统计使用。始终返回 `{"code":0}`。

## 8. 端到端验收脚本

```powershell
$BASE = "http://localhost:9002"
$UID  = "u-2001"

# 0) 健康检查
curl.exe "$BASE/healthz"
curl.exe "$BASE/readyz"

# 1) 创建直播间
$r = curl.exe -s -X POST "$BASE/api/v1/live/rooms" `
  -H "X-User-Id: $UID" -H "Content-Type: application/json" `
  -d '{"title":"Go 并发实战直播","notice":"今晚 8 点"}' | ConvertFrom-Json
$rid = $r.data.roomId
"roomId = $rid"

# 2) 开播（拿到新的 streamKey 与 pushUrl）
$s = curl.exe -s -X POST "$BASE/api/v1/live/rooms/$rid/start" -H "X-User-Id: $UID" | ConvertFrom-Json
"status = $($s.data.status)  session = $($s.data.sessionId)"
$key = $s.data.streamKey

# 3) 有 SRS 时：# ffmpeg -re -i demo.mp4 -c copy -f flv "$($s.data.pushUrl)"
#    无 SRS 时，用调试接口模拟 SRS 回调
curl.exe -X POST "$BASE/api/v1/live/dev/publish/$key?session=$($s.data.sessionId)"

# 4) 确认状态已变为 LIVING，并取播放地址
curl.exe "$BASE/api/v1/live/rooms/$rid"
curl.exe "$BASE/api/v1/live/rooms/$rid/play"

# 5) 3 个不同用户上报心跳 → onlineCount 应为 3
1..3 | ForEach-Object {
  curl.exe -X POST "$BASE/api/v1/live/rooms/$rid/heartbeat" -H "X-User-Id: u-30$_" | Out-Null
}
curl.exe "$BASE/api/v1/live/rooms/$rid/online"

# 6) 关播
curl.exe -X POST "$BASE/api/v1/live/rooms/$rid/stop" -H "X-User-Id: $UID"

# 7) 越权校验：他人关播应 403
curl.exe -X POST "$BASE/api/v1/live/rooms/$rid/start" -H "X-User-Id: u-9999"

# 8) 直播历史
curl.exe "$BASE/api/v1/live/rooms/$rid/records" -H "X-User-Id: $UID"
```

## 9. 与 danmaku-service-go 的衔接

弹幕服务需要知道「房间是否在直播」，有两种方式：

| 方式 | 说明 | 本服务需要做什么 |
| --- | --- | --- |
| **订阅事件**（推荐） | 订阅 `live.started` / `live.stopped`，自行维护 Redis 状态 | 已经发布，无需改动 |
| **HTTP 查询** | 调 `GET /api/v1/live/rooms/:id/online` 或详情接口 | 已提供 |

弹幕服务在收到 `live.stopped` 后会：
1. 把房间内所有 WebSocket 连接广播「直播已结束」；
2. 触发最后一次弹幕批量落库；
3. 清理房间 Hub 与 Redis 热数据。
