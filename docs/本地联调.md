# 本地端到端联调

记录一次真实起全栈联调的可复现步骤，以及**只有真跑起来才会暴露**的问题。
自动化验证见 [`../../web/e2e-real/live-real.spec.ts`](../../web/e2e-real/live-real.spec.ts)。

---

## 0. 最快路径：一条命令

```powershell
cd media-platform-backend/deploy
.\dev-up.ps1          # 起 infra（若未起）→ 导表 → 建桶 → 构建 → 启动 8 个服务
.\dev-down.ps1        # 停服务 + 停基础设施（-KeepInfra 只停服务）
```

脚本会自动处理：容器 MySQL 口令、`.env` UTF-8 解析、SRS 8001 端口冲突、FFmpeg 路径探测、
端口就绪等待，并把日志/PID 写到 `deploy/runtime/`。

> 以下章节是**手工步骤**，用于排错或理解脚本在做什么。

## 1. 启动基础设施

```powershell
cd media-platform-backend/deploy
docker compose --profile infra up -d mysql redis rabbitmq minio nacos
docker compose --profile media up -d srs
```

验证端口：`3307`(MySQL) `6380`(Redis) `5672`(RabbitMQ) `8848`(Nacos) `9000`(MinIO) `8088`(SRS HTTP)。

> **minio/mc 拉不到时**（Docker Hub 返回 pull access denied）：
> 跳过 `minio-init`，改用 Go 命令建桶 + 匿名读策略：

> $env:VIDEO_MINIO_ENDPOINT='127.0.0.1:9000'
> go run ./cmd/bootstrap-minio
> ```

## 2. 建表与种子数据

`deploy/db/go/media-tables.sql` 会在 MySQL 容器**首次初始化**时自动执行（含 S4 的点赞/收藏表）。

商品 / 订单表需要手工导入：

```powershell
docker cp media-platform-backend/product-service/src/main/resources/db/schema.sql gomedia-mysql:/tmp/p.sql
docker cp media-platform-backend/order-service/src/main/resources/db/schema.sql   gomedia-mysql:/tmp/o.sql
docker cp media-platform-backend/deploy/db/seed-media.sql                          gomedia-mysql:/tmp/s.sql
# 容器内执行（避免 PowerShell 管道重编码中文）
docker exec gomedia-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 auth_service < /tmp/p.sql'
docker exec gomedia-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 auth_service < /tmp/o.sql'
docker exec gomedia-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 auth_service < /tmp/s.sql'
```

## 3. 启动服务（本机直跑，避免反复构建镜像）

> **数据库账号**：以 `docker exec gomedia-mysql printenv MYSQL_ROOT_PASSWORD` 为准。
> `.env` 中的口令可能与容器实际 `MYSQL_ROOT_PASSWORD` 不同（Compose 插值等原因），直连服务时不要直接复用。
>
> **PowerShell 读 `.env` 必须加 `-Encoding UTF8`**：文件是 UTF-8 无 BOM，而 PowerShell 5.1 默认按 ANSI 解码，
> 会把某些多字节字符的尾字节与换行一起吞掉，导致 `RABBITMQ_USER` 等键被解析成空串（见 I-017/E-005）。

### Go 服务

```powershell
# video-service（在 video-service-go 目录）
$env:APP_ENV='local'
$env:VIDEO_MYSQL_DSN='root:<容器口令>@tcp(127.0.0.1:3307)/auth_service?charset=utf8mb4&parseTime=True&loc=Local'
$env:VIDEO_REDIS_ADDR='127.0.0.1:6380'
$env:VIDEO_RABBITMQ_URL='amqp://admin:admin@127.0.0.1:5672/'
$env:VIDEO_MINIO_ENDPOINT='127.0.0.1:9000'
$env:VIDEO_MINIO_PUBLIC_ENDPOINT='http://127.0.0.1:9000'
$env:VIDEO_MINIO_BUCKET='media'
$env:VIDEO_TRANSCODER_DRIVER='real'
$env:VIDEO_FFMPEG_PATH='C:/Program Files/ffmpeg-7.1-full_build/bin/ffmpeg.exe'  # 用正斜杠
go run ./cmd/server -config configs/config.yaml
```

`live-service` / `danmaku-service` 同理，分别用 `LIVE_*` / `DANMAKU_*` 前缀；直播另需
`LIVE_MEDIA_DRIVER=srs`、`LIVE_SRS_API_BASE=http://127.0.0.1:1986`、
`LIVE_PUBLIC_BASE=http://127.0.0.1:8088`。

### Java 服务

| 服务 | 端口 | 关键环境变量 |
| --- | --- | --- |
| user | 8001 | `MYSQL_URL`/`MYSQL_USERNAME`/`MYSQL_PASSWORD`、`NACOS_*`、`DUBBO_PROTOCOL_PORT=-1` |
| auth | 8002 | `SPRING_DATASOURCE_URL`/`PASSWORD`、`SPRING_DATA_REDIS_*`、`AUTH_JWT_SECRET`、`DUBBO_REGISTRY_ADDRESS=nacos://127.0.0.1:8848` |
| product | 8003 | `SPRING_DATASOURCE_URL`/`PASSWORD`、`NACOS_*`、`DUBBO_PROTOCOL_PORT=20880` |
| order | 8004 | 同 product、`PRODUCT_RPC_URL=dubbo://127.0.0.1:20880`、`MOCK_PAY_ENABLED=true` |
| gateway | 8000 | `JWT_SECRET`（与 auth 一致）、`SPRING_DATA_REDIS_*`、`USER_SERVICE_URI`、`VIDEO/LIVE/DANMAKU_SERVICE_URI` |

`spring-boot:run` 在部分 JDK 22 环境会报 `ClassNotFoundException`，改用：

```powershell
mvn -q -DskipTests package
java -jar target/<service>-*.jar
```

### 演示账号与管理员

| 账号 | 密码 | 说明 |
| --- | --- | --- |
| `13800138001` | `password123` | 数据最全；本地已提升为 **ADMIN**（可进 `/admin`） |
| `13900139001` | `password123` | 普通用户，可用于测关注/粉丝 |

管理员由 `user.role` 决定（`0=ADMIN`，`1=普通用户`），登录时经 Dubbo 写入 JWT 的 `role` claim：

```sql
UPDATE auth_service.user SET role = 0 WHERE uid = '<你的 uid>';
```

改完需要**重新登录**才会签发带 ADMIN 的 token；前端「管理」入口由 `/users/me` 的 `role` 控制。

## 5. 联调中踩到的坑（已修，细节见《开发问题记录》）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| `/api/v1/profiles` 404 | 白名单放行了，但网关没有对应路由 | 路由加 `/api/v1/profiles/**` |
| `/users/me` 200 但响应体为空 | Dubbo `instance` 模式把 `user-service` 注册到 20881，网关 lb 把 HTTP 打到 Dubbo 端口 | Dubbo 改 `register-mode: interface`；网关直连 `USER_SERVICE_URI` |
| 点赞/收藏都返回 `false` | 视频读接口在 `permit-all`，身份头被剥离 | 迁到 `optional-auth` |
| 直播间一直 404 | 前端 `/live` 路由与媒体反代 `/live` 前缀冲突 | 前端路由改 `/streams` |
| 刷新页面后掉登录 | 刷新接口字段是 `accessTokenExpiresIn`，前端读 `expiresIn` | 两个字段都兼容；只有 401 才清会话 |
| 真实转码必失败 | `work_dir` 是相对路径，而 ffmpeg 的 `cmd.Dir` 被切到输出目录 | 工作目录转绝对路径 |
| 在线人数恒为 0 | `/online` 在状态缓存缺失时直接返回 0 | 缓存缺失也读心跳 ZSet |
| 带 `?` 的中文变成 `???????` | 测试客户端没用 charset=utf-8 发请求 | 客户端显式 `charset=utf-8`；服务端本身正常 |
| SRS 占用 8001 导致 user 起不来 | compose 把 WebRTC 映射到 8001，与 user-service 冲突 | `SRS_WEBRTC_HOST_PORT=8100` |
| RabbitMQ 403 | `.env` 被 PowerShell 按 ANSI 解码，`RABBITMQ_USER` 变空串 | 读取时加 `-Encoding UTF8`；已确认 `eventsDriver=rabbitmq` |
| OBS 推流被拒：`app 不匹配`（70002），60s 后房间变「开播失败」 | 把 `<streamKey>` 填进了 OBS「服务器」栏，密钥栏只填了 `<session>`，SRS 解析成 `app=live/<streamKey>` | 服务器只填 `rtmp://host:1936/live`；串流密钥填 `<streamKey>?session=<sessionId>`（两段都要）；页面已拆成两栏分别复制 |

## 6. 已知演示限制

- `seed-media.sql` 的直播间状态是 `LIVING`，但没有真实推流：播放地址能拿到，播放器会等流；
  在线人数来自心跳 ZSet，不是真实观众。
- 种子视频/直播间的作者现在是 `1001–1004` 的演示用户（seed 已写入 `user` 表），作者卡可正常显示昵称。
- 想验证完整直播链路：直播管理页创建房间 → 开始直播 → 按页面给出的「服务器 / 串流密钥」两栏填 OBS；
  推流成功后状态自动变 `LIVING`，结束推流自动 `ENDED`。
