# user-service 测试文档

## 1. 测试目标

验证设计方案定义的全部 P0 需求：通过 Dubbo 创建用户、查询当前用户、单个查询、批量查询、存在性判断、资料修改、状态查询、用户注销和管理员状态管理。

## 2. 测试环境

- JDK 22（项目编译目标为 Java 17）
- Maven
- Spring Boot Test + MockMvc
- Dubbo Provider 集成测试
- H2 内存数据库
- 测试 profile：`test`
- 测试命令：

```powershell
mvn test
```

测试使用 `src/test/resources/application-test.yml`，不会连接生产 MySQL。生产启动使用 `application.yml` 中的 MySQL 配置。

## 3. P0 测试用例

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| P0-01 | Dubbo 创建用户资料 | RPC 成功响应，生成唯一 `uid`，状态为 `NORMAL` |
| P0-02 | HTTP 查询当前用户，携带 `X-User-Id` | HTTP 200，返回完整资料 |

## 4. 自动化覆盖

`UserControllerIntegrationTest` 当前自动化覆盖：

- Dubbo 创建用户并按 ID 查询
- 当前用户逻辑注销
- 当前用户资料修改
- 管理员查询用户状态
- Dubbo 单次批量查询
- Dubbo 批量存在性查询，包含不存在 ID
- 普通用户权限拒绝
- 管理员状态修改

## 5. HTTP 手工接口检查

启动服务：

```powershell
mvn spring-boot:run
```

查询当前用户：

```powershell
curl.exe http://localhost:8080/api/v1/users/me -H "X-User-Id: 1"
```

管理员禁用用户：

```powershell
curl.exe -X PATCH http://localhost:8080/api/v1/admin/users/1/status `
  -H "X-User-Id: 99" -H "X-User-Role: ADMIN" `
  -H "Content-Type: application/json" -d '{"status":"DISABLED"}'
```

逻辑注销：

```powershell
curl.exe -X DELETE http://localhost:8080/api/v1/users/me -H "X-User-Id: 1"
```

## 6. Dubbo 验证

Dubbo Provider 默认暴露在 `20880`，注册中心地址为 `N/A`，采用直连模式。消费者依赖 RPC API 后，通过 `@DubboReference UserDubboService` 调用四个方法：`createUser`、`getUser`、`batchGetUsers` 和 `checkUserExists`。当前自动化测试通过 Spring 容器注入 Provider 接口验证完整业务链路。

## 7. 最近一次执行结果

执行命令：

```powershell
mvn -Dtest=UserControllerIntegrationTest test
```

结果：通过，6 个测试全部通过。Spring Boot 成功启动，Dubbo Provider 在 `20880` 暴露，测试使用 H2 `test` profile；`createUser` 生成与 account 共享的 `uid` 并写入 `user` 表，HTTP 资料更新、状态管理、逻辑注销以及 Dubbo 按 uid 单查、批量查询、存在性查询均正常。

## 8. 风险与后续测试

- 当前测试未连接真实 MySQL，发布前应在集成环境执行一次 MySQL 8 验证。
- `X-User-Id` 和 `X-User-Role` 必须由可信网关覆盖，不能让公网请求直接伪造。
- 后续 P1 需要增加事件通知、搜索和扩展资料测试。
- 建议补充并发状态修改、超长批量 ID、数据库连接异常和慢查询测试。
